# Review Notes: ZSV_PO_OPEN_LIST (Phase 1 ABAP)

## 1. Explanation
**Summary.** A classic report that lets a buyer enter supplier and PO-date ranges, reads purchase
order headers (EKKO) joined to items (EKPO), and shows PO number, supplier, date, item, material
and quantity in an ALV grid.

**Walkthrough** (line numbers refer to phase1_source.abap)
1. L2-6: selection screen, with select-options for supplier (LIFNR) and PO date (BEDAT). The helper
   variables are only there to type the select-options; they are fine and avoid the obsolete TABLES.
2. L8-15: one inner join of EKKO and EKPO on EBELN. The WHERE clause applies both ranges and the
   result goes into the inline table LT_PO.
3. L16-26: builds a SALV table from LT_PO and displays it; an empty CATCH ends the block.

**Dependencies:** tables EKKO, EKPO; class CL_SALV_TABLE; exception CX_SALV_MSG.

**Risks / gaps**
| Area | Finding | Severity |
|---|---|---|
| Name vs behaviour | Called "open list" but nothing restricts to open items. Deleted items (EKPO-LOEKZ), delivered items (ELIKZ), and non-PO document types (EKKO-BSTYP: RFQs, contracts) are all returned. **Needs business confirmation.** | High |
| Security | No AUTHORITY-CHECK (purchasing org / document type). Any user can list all suppliers' POs. | High |
| Error handling | Empty CATCH (L25) hides a failed ALV build; the user sees nothing. | Medium |
| Quantity | MENGE is selected without MEINS, so quantities have no unit. | Medium |
| Usability | No message when nothing is found; no ORDER BY, so the row order is not guaranteed. | Low |
| Style | LO_ALV is global but only used inside the event (L4). | Low |

## 3. Testability
- **As written: not unit-testable.** The logic sits in START-OF-SELECTION and ABAP Unit cannot
  call an event block. The ALV display is UI.
- **Refactor (zsv_po_open_list_final.abap):** selection logic moved to `LCL_PO_OPEN_LIST->GET_PO_ITEMS`
  (same join and filters, plus MEINS and a stable ORDER BY); display moved to `DISPLAY`; empty-result
  message and real error handling added. The original is untouched in phase1_source.abap.
- **DB isolation:** EKKO and EKPO are replaced with test doubles via CL_OSQL_TEST_ENVIRONMENT, so the
  tests never read real data. If your release lacks this class, the alternative is to pass the data
  in as a parameter and test the filter logic on internal tables.
- **Not unit tested:** the ALV rendering (UI) and authorization.
